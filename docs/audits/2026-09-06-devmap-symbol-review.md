# DevMap UI 组件与地铁符号调查

日期：2026-09-06。范围：当前开发工作区的地图 UI、条件性详情和导航；本轮不修改产品代码。

Method: dual-agent (A: symbol_ui_inventory · B: symbol_mechanical_review)。A 独立阅读组件与截图，B 独立检查实现、几何和检测器，主任务核对官方交通设计资料并综合判断。

## 结论

值得学习的是稳定的符号含义、站点层级、线路出口指引和标签布局。实线历史、虚线意图、独立工作区平台、乘客与详情区已经具备正确基础，应保留。优先处理两类问题：信息含义不明确，以及关键内容看不清/点不到。无需全面换肤、扩大图标库或为了外观增加线路。

产品仍以真实 Git 为准：提交是节点，父子边是历史；Worktree 附着在 HEAD；聊天是乘客；subagent 是父任务下的协作者。Git 分叉点不自动等于 Worktree 创建点，未来交付不保证产生 merge commit，地图来源也不等于 Agent 执行目录。

| Git 父子轨道 | 彩色粗实线、主干黑色 | 保留；线色标识路线，不承担成功/失败状态 |
| 路线转弯 | 正交折线/曲线 | 已可用；45° 只在减少绕行或交叉时采用 |

| 多工作区共享 HEAD | 一个站，平台标题 +N | 保留单一真实站；改为明确的“2 个工作区”，展开选择具体目录 |
| 引用数量 | main · tip +N | 改为“2 个引用”等带单位计数，不能与工作区 +N 混用 |
| 地图来源和选择 | Map source 蓝底标记、选择态 | 含义必须独立；来源不能借用“我在这里”的乘客定位符号 |
| 当前旅程条 | 工作区、起点/共同祖先、HEAD、目的地、Focus journey | 保留；390px 下目的地状态需要无需横向滚动即可辨认 |
| 乘客 | 人形图标、观察数量、聊天列表 | 已够用；显示已观察数量和清单是否完整，不把名单不完整写成已知乘客也不存在 |
| subagent | 父任务下 Collaborating agents 折叠列表 | 保留；不增加乘客总数，不因协作者存在就画独立轨道 |
| 脏工作区/未发布/已纳入 | 平台短文本，详情展开 | 保留证据驱动状态；不要让整条分支因 dirty 变成警报色 |
| 保留工作区 | 弱化平台、Retained workspace 文案 | 可用；修复边框变量和弱化后的可读性 |
| 未来路线/目的地 | 虚线、独立 arrival 区域、计划站点 | 保留虚线与独立区域；未来标记不应被看成真实提交；文案改为尚未观察到交付 |
| 里程碑/路线计划详情 | 可展开目标、条件、来源、修订与状态 | 结构够用；只有执行证据存在时才显示已完成等事实 |
| 图外连续线路 | 下方 connections beyond view 列表 | 保留导航；在已知轨道出口增加指向图外的箭头和端点短名更直观 |
| 工具栏 | 缩放、Full map、Locate、More、平移 | 常规控件已够用；不需要改造成列车操纵台 |
| 工作区总览/分支索引 | 折叠列表与跳转 | 保留，作为长名称、同色线路、共享平台的查找入口 |
| Commit 详情 | SHA、引用、时间、父子导航、复制 | 保留；全量技术信息放在选中后的详情中 |
| Worktree/聊天详情 | 身份、任务打开、生命周期、活动、执行位置来源 | 保留；可访问名称应包含关键人数/风险摘要，不只含路径和 ID |
| Observations/刷新/覆盖范围 | Git 与任务数据新鲜度、计数、刷新、覆盖提示 | 保留数据源区分；公共不确定性说明集中一次，个别异常再单独标注 |
| 风险和反馈 | 三角警告、未知标记、干预列表、导航反馈 | 区分需干预与证据不足；未知不是故障，dirty 也不必然需要警报 |

## 官方符号对照与适配边界

TfL 将普通站刻度、换乘圆圈、平台间连接、线路色签和图外延续箭头分别定义；方向变化允许 45° 或 90°，间距与文字尺寸有关。对 DevMap 的建议是借鉴这种分工和比例纪律，而不直接复制每个符号。特别是图外延续箭头只用于已知路线超出显示范围，不能兼任“未来计划”或“历史未知”。来源：[TfL Line diagram standard，第 7、9–12 页](https://content.tfl.gov.uk/tfl-line-diagram-standard.pdf)。

TfL 的站台线路图帮助乘客在决策位置判断平台与目的地。我们已有“全图 + 所选旅程条 + 详情”的结构，值得继续使用，而无需把任务全文放进地图。[TfL Interchange signs standard，第 36 页](https://content.tfl.gov.uk/tfl-interchange-signs-standard.pdf)。

同时查阅 [MTA 官方地图](https://www.mta.info/map/5256) 与 [TfL 官方 Tube map](https://content.tfl.gov.uk/standard-tube-map.pdf)。各系统图例有自身含义，本轮不把某个城市的实心/空心圆当成通用标准。官方 PDF 的依据是可提取的标准文字；不声称已完成其 PDF 渲染图的视觉检查。

适配建议：

- 工作区共享一个 HEAD，可借鉴共享站台的组织方式，但仍只有一个 Commit 节点；不得为了画哑铃换乘图标增加假节点。
- 普通点、拓扑接点、工作区关联、未来路线、图外延续、未知边界需要可读的图例。既有含义清楚的图形不必换掉。
- 分支使用颜色加文字；虚线已经专门表示意图，不应再被复用为另一条真实分支的区分样式。
- 机场、轮椅、河流、收费分区没有对应产品事实，不能照搬成 Agent、空闲或权限符号。
- 活动状态没有实时位置证据时，不显示沿轨道移动的列车。PR、锁、检查结果不成为没有证据的假车站。

## 两项优先工作

### P1：让关键符号、计数和状态只有明确的一种解释

源码依据：`dock.html:274` 的常驻图例仅三项；`:872` 的 +N 表示工作区，`:1012` 的 +N 表示引用；`:1021` 的计划文案预设未知 merge commit；`:431`、`:635`、`:837`、`:1203` 重复清单不完整与状态未知。

行动：补完整的小图例；为边界单独标记；数量带对象单位；将计划说明改为“尚未观察到交付”；统一“已观察到 1 个聊天，清单不完整”等文案。保留来源/选中/Agent 报告位置的不同含义。无需扩大所有节点的图标种类。

验证标准：初次打开者可以区分事实与计划、分叉与工作区创建、图外与未知；同一个 +N 不再需要猜对象；fast-forward 交付没有被暗示为必然产生合并提交。

### P1：让真实关系与关键文字在窄侧栏仍然可见

源码和截图依据：

- 516px 截图中 History splits 标签被平台遮挡；布局避让只包含平台，junction/main-tip 标签在之后追加（`metro-core.js:834`、`dock.html:1001`、`:1013`）。
- 非所选旅程平台整体 opacity .55，常规/次要文本组合后的对比度估算约 3.71:1 / 2.47:1（`dock.html:218`）。这是样式计算结果，不是完整无障碍认证。
- 黄色轨道有深色轮廓，但黄色站点没有；黄与底色对比度估算约 1.42:1（`dock.html:219`、`:610`、`:901`）。
- 站点交互区域为 24×24px，75% 缩放时约 18×18px；项目设计目标为 44px，密集节点没有显式最小间距（`dock.html:219`、`:941`；`metro-core.js:782`；`DESIGN.md:226`）。

行动：统一处理站名、平台、引用标签的避让；弱化背景和线条而保持文字可读；给浅色节点补深色轮廓；扩大独立点击区域，密集时提供选择列表或保留节点的折叠策略。扩大命中区时不能造成相邻节点相互遮蔽。窄屏目的地短状态保持可见。

验证标准：390/516px 下关键标签无覆盖，乘客和目的地可读；选择旅程之后仍能读懂其他平台；黄色节点可见；点击区域不随视觉缩放降到难以使用的大小。

## 后续候选，不列为本轮必做

- 图外端点箭头接入现有导航；区分已知延续、未知边界、实际根提交。
- 在关键路口添加颜色加短分支名的路线标识，复用已有分支索引而非增加另一套分支身份。
- 多条未来路线共用固定走廊，可能重叠成一条虚线（`metro-core.js:886`）。应先用多计划数据验证，再决定分配独立走廊；当前截图没有该状态。
- 普通历史折叠只有在路线仍过长时再做；保留 forks、merges、refs、HEAD、计划锚点和边界。
- `--border` 未定义导致 retained-workspace 边框声明无效（`dock.html:214`），属于可随相关样式修复处理的小问题。

## 使用者影响

- 初次使用者：常驻图例无法解释同图中的点、单圈、双圈和边界；+N 不能辨认对象。
- 熟悉 Git 的开发者：可能把来源标记理解为当前执行工作区，把未来交付理解为一定会产生 merge commit。
- 手机/窄侧栏使用者：目的地横向裁切、相似长分支名截断、小站点难点、弱化后文字难读。
