# 代码交付与人工验收：当前执行要求

2026-09-13，用户明确修改要求：“修改goal尽快完成代码，验收改为我人工验收”。本要求优先于此前两阶段自动验收合同及旧 Goal 文本中的自动验收闭环。

## 当前目标

在已有独立 worktree 和 `codex/devmap-sqlite-compatible` 分支完成 Rust + 仓库级 SQLite + 按需共享核心代码收尾，保持既有网页版与 `devmap/dock/4` 兼容，提供可运行构件、启动说明和已知限制，由用户人工验收。

保留必要的构建、相关回归和数据保护检查。停止追加 A/A 校准、正式性能人口、十分钟资源复测和跨平台验收；这些不再作为本次代码交付的自动阻塞项。历史失败、未验证范围与性能目标继续保留，不改写成通过。用户反馈实际问题后再做有针对性的修复，不自动恢复原来的无限验收循环。

## 交付边界

- 复用已构建且与生产源码对应的 Windows 候选；源码未改动时不为更新文档重复构建和全量回归。
- 交付时记录源码版本、程序哈希、必要检查与入口。用户实际体验、性能是否可接受及宿主自动 hooks 最终结果由用户确认。
- 之前为助手开展真实 hooks 验收而提出的隔离信任授权请求不再阻塞本任务，也不视为已获授权；助手不修改信任记录。
- 继续保护旧数据、其他工作区、已安装插件和全局配置。不自动迁移真实用户库、合并、推送、安装或发布。
- “代码已交付、待人工验收”与“产品已通过人工验收”分开记录。完成本次代码交付不宣称原性能指标、全部宿主或全部平台已经验证。

Goal 工具仅支持读取、创建、完成与阻塞，不能原位编辑已有目标文本。执行时以本次用户修订为准；不修改工具内部存储，不创建重复活动目标。
