## 第一阶段性能：先校准并冻结，再验候选

已有候选 smoke 已被观察过，因此本轮是公开的前瞻性验收，不宣称盲测。它们只能用于可行性与测量设计，不能充当新的验收样本。

1. 选择并记录冻结旧版与候选的 SHA、前端来源、机器/电源状态、运行命令、缓存条件和唯一隔离数据集。旧版读取旧存储，候选读取从同一记录导入的 SQL；两者完整逻辑输入先对照。保留源和备份。
2. 公共路径采用双方都有的 devmap_read_map，以及同一浏览器“首个有效地图可交互”边界。新摘要端点的结果单列，不能与旧全量地图宣称等价性能。确认旧接口的刷新行为，不能给一边额外缓存或跳过 Git 刷新。
3. 先运行 **仅旧版 A/A 校准**，检查计时边界、噪声、正常等待反馈和失败诊断。校准报告必须说明容忍度与旧版实际体验的关系。没有校准证据，不能冻结为可执行通过门槛，也不能开始正式候选人口。
4. 预先限定工程容忍度的最大边界：候选 p95 回退最多为基线 p95 的 10%，同时热交互增量不超过 100 ms，冷打开/变更可见增量不超过 250 ms，取二者较小值。这些是保守工程预算上限，不是“所有用户都感知不到”的研究结论。校准只能收紧，不能超过这些上限；若 A/A 噪声已无法分辨该幅度，先改善测量环境，不能扩大门槛。
5. 可感知体验独立验收：原有加载反馈不得消失，不新增手工步骤或卡死/失效状态；对照实际页面响应，记录首个反馈、首个有效内容和交互完成时刻。对旧版已有慢路径如实报告，不能因为“同样慢”就声称达到第二阶段目标。校准报告若不能支持此判断，用户无感仍未证明。
6. 在候选正式人口启动前，提交 benchmark-contract.json 及其 SHA，写入上述收紧后的明确数值、视口/事件/计时点、样本种子与分析方法。结果出来后禁止改门槛；需要修改时保留失败，另立明确的新协议。
7. 至少三轮独立成对运行，顺序按预先记录的 AB/BA 安排：每版本每轮 20 次独立冷启动；四客户端各 10 次预热、至少 100 次测量；变更可见每轮 100 次并保留四客户端结果。不得删除慢样本、超时或重启失败；刷新影响样本和无全量刷新子集都报告。改变一个测试因素必须两边相同。
8. 报告每轮和合并人口的 p50/p95、错误数、置信区间与最大响应大小。预注册按成对运行/时间块 bootstrap，不能把相关的同批四客户端当作四个独立实验。各客户端与各轮都不得被总体均值掩盖；置信区间无法排除超限回退则结论为未证明，排查噪声或修复后按协议再测。
9. 正式比较使用相同后台空闲/重启边界；每个冷样本确实没有复用前一实例。现有 process-performance.cjs 不证明候选 owner 已退出，不能直接当最终对照工具。先补齐双方进程拥有者、生命周期与数据保护，再执行。

## 简化验收账本

对旧版与候选分别实际记录，不能只比较架构图。表中所有“待测”在第一阶段交付前必须有数量、命令/截图和用途说明。

| 项目 | 对比方式 | 通过规则 |
|---|---|---|
| 首次安装/接入步骤 | 下载/启动/宿主信任审核/配置的用户动作逐项计数 | 必需步骤不得增加；共同宿主安全审核单列，不伪装为已自动激活 |
| 必需配置项 | 全局一次性项、每仓库项、每 worktree 项分别统计 | 日常新增仓库/工作区不得增加手工维护配置 |
| 持久化文件种类 | 活跃权威数据、派生缓存、IPC/锁、迁移备份、legacy-only 分列 | 显示真正合并的活跃权威文件；不删除旧备份来制造数量下降 |
| SQLite 辅助文件 | devmap.db、正常 WAL/SHM、临时日志各自寿命与备份方法 | 不宣传“运行时只有一个文件”；使用一致性备份，不裸拷贝活跃主文件 |
| 后台进程 | 单客户端/四客户端的核心、轻代理、临时 Git/helper 分别计数 | 一个共享写核心；总进程数即使增加也必须如实报告，不混同核心数 |
| 生命周期 | 首次打开、并发打开、最后客户端退出、空闲、强杀恢复 | 自动按需启动/退出，无孤儿、无未知 PID 终止 |
| 日常维护 | 用户是否要建库、启动服务、清缓存、移动数据或手工修复 | 正常使用无需新增维护动作；故障恢复操作单列 |

第一阶段至少要证明一项有实际用户或维护价值的减少，并证明其余日常必需操作未增加。若仅换用 SQLite 而仍需同样的多份权威状态和手动操作，则“简化”不通过。

## 实际宿主与平台范围

- 第一阶段明确限定为当前 Windows 本地磁盘环境的可替换候选：真实 Codex CLI MCP 往返、用户使用的 Codex 内嵌浏览器流程、自动 hook 的信任/触发/落库与重开，均须有实际证据。说明所测 Windows/Codex/浏览器版本。只验证了 CLI MCP 不能关闭自动 hook 或桌面打开流程。

- 用户已要求保护已安装版本。任何实际宿主测试均使用隔离配置/仓库，不修改其现用插件、数据或全局信任记录。宿主要求用户审核时保留该安全流程，不使用绕过信任参数冒充实际接入完成。
